# admission-causal-v1 — lab pre-registration (synthetic, isolated)

Status: **frozen before execution**. Date: 2026-09-22. Track: **synthetic
lab**. Closes the P4 family on its fixture
(`docs/ADMISSION_PORTFOLIO_V1_PREREG.md` execution record) and tests the next
named hypothesis: **causal retrieval**, not another portfolio.

## 1. Hypothesis

A causal query must retrieve causal **relations**; changing only admission
does not rescue missing or buried evidence.

> Evidence needed for "why" questions arrives through explicit relations
> (decision -justified_by-> rationale), not through lexical similarity.

## 2. Substrate (new lab fixture)

`eval/fixtures/admission_causal_v1/` generated by
`eval/gen_admission_causal_v1.py`: 40 cases (4 scenarios x 10), 320 records,
60 gold occurrences, **relations embedded** in the records
(`justified_by`, `based_on`, `supersedes`). Design-time invariant verified
with the product BM25 before writing: in `causal_buried` and `causal_chain`
the rationale is buried (rank > 2, unranked counts as buried) while the
decision is discoverable (rank <= 2); in `causal_absent` no record carries
relations. Sample hash frozen in the manifest:
`cf597ae05fed3fc85e587e00beee56a6fe26f88fa8a5ef1e4b18bb5238bf3f33`.

| scenario | question | gold |
|---|---|---|
| `causal_buried` | "Why was X set to V?" with 6 strong decoys above the rationale | decision + rationale |
| `factual_control` | "What is X?" (same records) | decision only |
| `causal_absent` | causal question, **no justification exists**, 7 rationale-looking decoys | decision only (no invention) |
| `causal_chain` | "What led to the change?" old + new decision + rationale | new decision + rationale |

## 3. Retrieval and policies

- **Candidate source (baseline)**: product BM25 top-5 positive over the
  record texts (`summary + " " + why`).
- **Relation expansion (candidate retrieval)**: when the question carries a
  causal cue (`why`, `reason`, `led`, `motivo`, `justificativa`, `because`),
  add every record reachable at depth 1 from the top-3 lexical candidates
  following `justified_by` and `based_on` only (`supersedes` is **not**
  followed). Expansion records enter the candidate pool with their own BM25
  scores; the pool is deduplicated.
- **Policies**:
  - **B** = P3v4 (frozen module) over the baseline candidates - the current
    ranking baseline.
  - **K** = P3v4 (unchanged admission) over the expanded candidates -
    the candidate: retrieval change only.
  - **K-abl** = expansion for **every** query regardless of cue (gating
    ablation); the "no expansion" ablation is B by definition.

## 4. Metrics

Availability (gold / 60), precision (gold / delivered), per-scenario
availability and precision, delivered count, max per case, budget respected;
`undue_rate` on `causal_absent` = delivered non-gold / delivered (invention /
undue retrieval with no justification to find).

## 5. Gates (K; all required)

- **G1** availability >= 0.90.
- **G2** precision >= 0.70.
- **G3** causal wins: availability(K) > availability(B) on **both**
  `causal_buried` and `causal_chain`.
- **G4** factual control unharmed: availability(K) >= availability(B) on
  `factual_control` and precision there >= precision(B) - 0.05.
- **G5** negatives: on `causal_absent`, availability(K) >= availability(B)
  and `undue_rate(K) <= undue_rate(B) + 0.05`.
- **G6** gating matters: `undue_rate(K) <= undue_rate(K-abl)` on
  `causal_absent` or precision(K) >= precision(K-abl) on
  `factual_control`.
- **G7** determinism; **G8** budget/cap respected.

## 6. Expected readings (declared, not gates)

B cannot deliver the buried rationale (lexical-only); K adds it as a
candidate, but the frozen P3v4 admission may still reject it via the rare
floor and the relative gain floor - if so, the finding is that relations must
also inform **admission** (a relation slot, like the correction slot), and
G3 fails for a precise reason. K-abl is expected to inject noise on factual
queries.

## 7. Stop rules

Any gate fail: report, change nothing, re-fit nothing. A pass only prepares a
candidate for a future real window from zero (own pre-registration); it never
promotes. Lab results are non-evidence for product performance; template
overfitting caveat applies.

## 8. Execution protocol

Harness `eval/admission_causal_v1.py`, outputs
`eval/results/admission_causal_v1/report.json` and `report.md`,
`tests/test_admission_causal_v1.py` (regeneration equality, determinism,
recorded verdicts), proof regenerated, one primary run plus determinism
rerun, execution record appended, all committed.


## Execution record (2026-09-22)

Recorded run on the frozen lab fixture; determinism rerun identical.

| policy | availability | precision | delivered | undue (absent) |
|---|---:|---:|---:|---:|
| B baseline | 0.667 | 0.800 | 50 | 0.000 |
| K candidate | 0.667 | 0.800 | 50 | 0.000 |
| K-abl | 0.667 | 0.800 | 50 | 0.000 |

Per-scenario availability: `causal_buried` 0.50 / 0.50 / 0.50,
`causal_chain` 0.50 / 0.50 / 0.50, `factual_control` 1.00 (all),
`causal_absent` 1.00 (all).

Gates: G1 **false** (0.667 < 0.90); G2 **true**; G3 **false** (no causal
win); G4 **true**; G5 **true** (no undue retrieval); G6 **true** (vacuously
- see below); G7 true; `all_pass` **false**.

Findings:

- **Retrieval expansion works; admission rejects its evidence.** In C1-01
  the relation expansion added the buried rationale R08 to the candidate
  pool (rank 6, BM25 0.162), and the frozen P3v4 then dropped it: `rare =
  0.388` passes the 0.30 floor, but `gain = 0.147` against `0.60 x best
  (0.700) = 0.42` - the **relative gain floor** excludes relation-linked
  evidence whose lexical score is low. No causal availability is gained
  (0.50 both scenarios) and precision is unchanged.
- **The hypothesis "retrieval alone rescues buried evidence" is not
  supported**: the relation must also inform **admission** (a relation slot
  or relation-aware gain, as the correction slot did for supersession).
  This is the same lesson one layer deeper: first ranking vs admission,
  now retrieval-signal vs admission-signal.
- G6 passes vacuously: K-abl equals K because expansion only ever adds
  records in causal cases and the added records are always rejected by the
  same relative floor; the gating question is not decidable on this fixture.
- Controls behaved: factual availability 1.00 everywhere, no undue retrieval
  on the absent scenario (undue_rate 0.000), precision 0.800.

Stop rules applied: G1/G3 failed, nothing changed, nothing re-fitted. The
named next lab hypothesis: a **relation slot** in admission (structural
priority for depth-1 `justified_by`/`based_on` evidence on causal queries),
tested against this same frozen fixture with P3v4 as baseline. Lab-only
evidence; no production impact.
