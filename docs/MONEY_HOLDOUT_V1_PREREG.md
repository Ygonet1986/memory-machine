# money-holdout-v1 — pre-registration (W4 frozen, single holdout evaluation)

Status: **frozen before execution**. Date: 2026-09-22. Track: synthetic lab.

Step 1 of the owner's order after `numeral-inclusion-v1`: the money rule W4
was developed on one case (u3a-19) through three amendments, so it is
**exploratory**. This experiment freezes it and tests it once on a holdout
with money answers at different positions. **No rule change after seeing any
result.**

## 1. Frozen rule (pinned by source hash)

W4 is imported unchanged from `eval/numeral_inclusion_v1.py`
(`w4_window`); **source sha256:
`9023e734b94684bd9fdbb2b413c43b85a9f40ee6862465a45b146e4e4da5a707`**. Any
change to that function invalidates this evaluation. Baseline W1 = product
`fact_window`.

## 2. Holdout fixture (new, never used for the rule)

`eval/fixtures/money_holdout_v1/` (generated by `gen_money_holdout_v1.py`,
sample hash `1cfac6e7aeb6e2c83fc16bc979b4c09074cb2babef07d706ec03f86874930e53`):
12 cases, one money question each, the currency answer placed at declared
positions - **4 early / 4 middle / 4 late** - with two distractor amounts per
record. The generator does not reference W4; positions are the declared
design variable. Additionally, the untouched real-fixture case **u3a-24**
(gold `$1,300`, never inspected during W4 development) is a frozen external
check on delivery only.

## 3. Delivery stage (deterministic, no LLM)

Per case and arm, the required record is delivered as header + summary +
windowed `why` under a fixed allocation of 3600 characters; the phrase
metric (`phrase_delivery_v1`) checks the gold currency phrase.

- **H1 rule works on the new fixture**: currency phrase present under W4 in
  **>= 10/12** cases (and strictly more than under W1).
- **H2 positions**: the W4 advantage is not concentrated in one position:
  phrase present under W4 in at least one case of each of the three
  position groups where W1 fails. (If W1 never fails, report that the
  fixture was too easy - recorded, not re-fit.)
- **H3 external check**: u3a-24: phrase `1300$` present under W4 (delivery
  only; whatever W1 does is reported).
- **H4 budget/determinism**: every delivered item <= 3600 characters;
  two runs identical.

## 4. Answer stage (repeated, same answerer, blind judge)

Deterministic sample: the **first three case ids** (`H01`, `H02`, `H03`) x
arms W1/W4 x N=3 x 2 calls = 36 calls. Gate **H5**: score(W4) >=
score(W1) - 0.05 (no regression under repetition); individual deltas are
reported, not inferred from a single run.

## 5. Verdict

`all_pass` = H1-H5. Pass: the money rule survives an independent fixture
(still lab-only; a product-side claim would need the real window). Fail:
report; the rule stays exploratory and is not promoted. Either way, windows
remain **OFF** and no product default changes.

## 6. Threats

Synthetic records are templated; a single fixture cannot rule out
overfitting to money phrasing. The answer sample is three cases (noise floor
applies); the delivery stage carries the main claim. u3a-25 is excluded (its
gold has no currency value).

## 7. Execution protocol

Harness `eval/money_holdout_v1.py` (`--skip-llm` for delivery only), outputs
`eval/results/money_holdout_v1/{report.json,report.md}`,
`tests/test_money_holdout_v1.py`, proof regenerated, one run, execution
record appended, committed.

## Execution record (2026-09-22) — holdout did NOT validate the rule

Deterministic delivery stage (W4 source hash verified unchanged); no answer
stage was run because H1/H3 failed at delivery (the budget for the LLM gate
is preserved; prereg section 5 applies).

| reading | result |
|---|---|
| W1 present / W4 present (12 cases) | **12 / 12** (no difference) |
| positions | early/middle/late: no W1 misses (fixture too easy) |
| external u3a-24 (W4) | **false** - see cause below |

Gates: H1 **false**; H2 **false** (no position group where W1 fails - the
prereg's "fixture too easy" clause); H3 **false**; H4 true; H6 (rule frozen)
true; `all_pass` false.

Causes, named and not re-fitted:

1. **The synthetic holdout was too easy**: each record's `why` is shorter
   than the 3600-character allocation, so no truncation happens and W1
   delivers the same text as W4. The fixture property (text fit) was not
   checked at generation time; the prereg's H2 clause anticipated this
   outcome and forbids re-fitting it.
2. **The external check was the wrong instrument for u3a-24**: its gold
   `$1,300` is a **derived sum** (components `$1,000` + `$300` in M0012), not
   a literal currency phrase in the source records. A literal-phrase check
   cannot see a total that is never written; the component facts are present
   in the ingested memory. This is a composition-class case, not a delivery
   case for this metric.

Outcome: the money rule remains **exploratory and unvalidated**; nothing is
promoted and windows stay OFF. A corrected holdout (longer records that
force truncation; external checks restricted to single-source literal
currency golds, or component-based checks for derived totals) is the
declared next step before any rule claim. Rule unchanged throughout.
